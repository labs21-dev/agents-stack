# 問題類型 → 鏡頭路由表

| 問題類型 | 主力鏡頭 | 可省略 |
|---|---|---|
| UI/UX 設計決策 | 底層邏輯 + 心理學（含利害關係人）| 經濟學（除非涉及付費轉化）|
| 產品/商業策略定義 | 頂層 + 本質 | — |
| 用戶行為/付費/轉化問題 | 本質 + 逆向 + 經濟學 + 心理學 | — |
| 市場痛點驗證 | 本質 + 逆向 + 經濟學 + 心理學 | 底層邏輯（初期可簡化）|
| 資訊整理/深度研究 | 頂層 + 本質 + 逆向 | 經濟學、心理學 |
| 系統/agent 架構設計 | 底層邏輯 + 逆向（failure pattern）+ 常需額外鏡頭（資安/時序）| 經濟學、心理學（除非涉及成本控制/用戶體驗）|
| 人際/團隊協作問題 | 本質 + 經濟學（激勵）+ 心理學（信任 + 利害關係人）| — |

若問題橫跨多類，取聯集，但仍以「頂層→本質→底層→逆向」為必走骨架。

## 額外鏡頭（非預設，變數驅動）

不在此表內的鏡頭（如時間/資安/法律/生態）**不預設使用**。只在步驟 2 抽核心時發現某核心變數的機制六鏡都解釋不了，才依 `six-lenses.md` 的引入規則加入。引入後走同等深度產出，並記錄進 `emerging-lenses-log.md`。

> 反模式：不要因為「聽起來更全面」就預設加額外鏡頭——那是偽多樣性，會稀釋注意力預算。

## 降級規則

建完步驟 3 底層模型後，若核心變數間機制單純、不存在真正權衡取捨，允許跳過步驟 4-6 走簡化輸出。小題大作也是損耗。
