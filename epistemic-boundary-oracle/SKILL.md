# Epistemic Boundary Oracle（認識論邊界預言機）

一個會拒絕回答不可校準問題的預測路由器。不是「萬能預言機」，是「**知道自己在什麼邊界內可靠、在什麼邊界外必須沉默**」的路由器。

**對象**：要把「未來會怎樣」的問題變成可下結論問題的人——決策者、預測系統設計者、拿到一個預測架構要審查的人。

**Spirit**：拒絕是預設行為，預測是賺來的特權。預言機的價值不在「能預測多少」，在「拒絕得有多準」。

## 核心命題

可預測性不是架構層數的函數，是該域是否有**預先承諾的邊界 + 足夠同分布樣本**的函數。

```
predictable(domain) ⟺ 該域邊界在事件發生前可無歧義承諾
                     且存在足夠數量的、結果已知的同分布歷史預測
```

加層（世界模型、10^4 agent swarm、反事實引擎、強制因果接口）**不會**把不可校準的域變可校準。agent swarm 的可調參空間隨代理數增大，過擬合歷史的能力增強，對未來的預測力不升反降——「模型複雜度」被誤當成「預測力」是預測系統設計的核心錯誤。

## 何時觸發

使用者的請求符合以下任一特徵時啟動：
- 問「X 會發生嗎」「X 的機率多少」「未來會怎樣」——要對未來下機率結論
- 要設計 / 評估一個預測系統（含「萬能預言機」式通用預測架構）
- 拿著一個預測架構來審查，問「這個設計可行嗎」
- 已有預測，問「這個預測可信任嗎／校準過嗎」

**不要用在**：目標明確的執行任務、純事實查詢、可輕易回滾的低風險決策、純技術架構題（用 protocol-adversarial-design）、多方進入策略決策本身（用 structural-decision-stress-test——本 skill 是它的上游路由器，不是替代品）。

## Hard rules

1. **先分類，再回答。** 任何未來查詢先分到三類域之一，分類決定輸出形式。不分類就輸出機率 = 越界。
2. **拒絕是預設。** 第三類域不輸出機率，降格為條件式警戒或拒絕。不可校準不是缺陷，是事實；對它沉默是誠實，不是無能。
3. **機率只在可校準窗口內。** 第一類全窗口；第二類只在 2a + 短視野 + 觸發線已挂 + 軟改嫌疑低（見 `references/domain-classes.md`）。窗口外一律降格。
4. **不輸出單一數字。** 機率輸出必須是不可坍縮結構（條件機率鍵名 + regime 參照 + 觸發線 + 視野 + 置信等級）。單一數字 + 免責註腳會被下游忽略——坍縮一旦發生，條件依賴從承重結構變裝飾。
5. **不抹平尾巴。** 第二類的「regime 會不會變」第三類尾巴、2a 的軟改殘餘，必須顯式標記並被機制約束，不可坍縮進單一數字。見 `references/tail-defense.md`。
6. **第三類委派 SDST。** 第三類域（含 2b、長視野 2a）的條件式警戒輸出委派給 `structural-decision-stress-test`。本 skill 不自己造條件式警戒，只路由。

## Flow（每次調用）

### 0. 取出問題

把使用者的「未來會怎樣」問題取成精確形式：
- 被預測事件的精確定義（可觀測、可判定兌現）
- 兌現時間 / 視野
- 兌現判定方法（誰、依什麼證據）

定義不清 → 先要求釐清，不進分類。一個連「怎樣算發生」都說不準的問題，分類也無意義。

### 1. 域分類（核心步驟）

按 `references/domain-classes.md` 把問題分到三類之一。分類判準是**域邊界能否在事件發生前被無歧義承諾**，不是「有沒有樣本」：

| 類 | 邊界來源 | 樣本 | 輸出形式 |
|---|---|---|---|
| 第一類 | 獨立機制釘死（物理／數學） | 同分布可累積 | 機率分布（全窗口） |
| 第二類 2a | 制度公布可觀測邊界 | 制度穩定期內可累積 | 機率分布（窄窗口，帶置信等級） |
| 第二類 2b | 制度存在但預測者畫邊界 | 同分布性存疑 | 條件式警戒（委派 SDST） |
| 第三類 | 事後敘事 | 樣本數≈1，同分布性是事後編的 | 條件式警戒（委派 SDST）或拒絕 |

分類時逐項檢查 `references/domain-classes.md` 的判準與反模式。分錯類 = 整條鏈失效，這一步是 ceiling。

### 2. 視野-穩定性閘（第二類專用）

對第二類問題算 `horizon / regime 歷史穩定半衰期`。超閾值 → **自動拒絕輸出機率**，降格第三類路徑。長視野的第二類預測在這條規則下根本進不了機率路徑——它們是戴著第二類面具的第三類。見 `references/tail-defense.md` § 視野-穩定性比。

### 3. 依分類輸出

- **第一類** → `references/prediction-log.md` 的預承諾日志 schema + 機率分布。預承諾協議在這裡是純記賬紀律（防事後改定義），不是校準來源。
- **第二類 2a 短視野** → `references/prediction-log.md` 的不可坍縮輸出結構 + 觸發線 + 軟改嫌疑指數調節的置信等級。
- **第二類 2b / 長視野 2a / 第三類** → 委派 `structural-decision-stress-test`，輸出條件式警戒（「若 H 錯則切換到分支」），**不輸出機率**。
- **連條件式警戒都構不出的純混沌** → 拒絕，輸出 `⊘ 不可預測域` + 理由 + 「建議保留選項權」。

### 4. 標記殘餘

每個機率輸出必須標記其殘餘不確定性的來源與能否消除：
- 第一類：殘餘來自樣本有限，可隨累積消除。
- 2a 短視野：殘餘來自軟改可能正在進行而症狀未顯——**不可消除**，只靠短視野壓低權重（啟發式，非校準結論）。
- 2a 還帶「制度改革歷史是描述性、非預測性」標記。

不可消除的殘餘必須顯式標記為不可消除，不可偷換成「可校準且小」。

## 輸出契約

每次完成必須包含：

1. **QUERY_PRECISION** — 被預測事件的精確定義 + 兌現判定 + 視野（定義不清則要求釐清，不進分類）
2. **DOMAIN_CLASS** — 三類之一 + 判準依據 + 2a/2b 區分（若第二類）
3. **OUTPUT_FORM** — 機率分布 / 條件式警戒（委派 SDST）/ 拒絕，由分類決定
4. **CALIBRATION_EVIDENCE** — 若輸出機率：預承諾域、樣本數、Brier、校準曲線、視野-穩定性比、軟改嫌疑指數、置信等級
5. **RESIDUAL** — 殘餘不確定性來源 + 能否消除（不可消除的必須標記）
6. **TRIP_WIRES** — regime 可觀測量斷裂清單（斷裂 → 機率失效、樣本歸零）
7. **REFUSAL_OR_DELEGATION** — 若拒絕或委派：理由 + 建議（保留選項權 / 呼叫 SDST）
8. **TAIL_DEFENSE_LOG** — 本次用了哪些尾巴防禦機制（不可坍縮結構 / 視野閘 / 觸發線 / 軟改指數），證明尾巴沒被抹平

## Sibling split

| 需求 | Skill |
|------|-------|
| 多方進入策略決策（承重實體、博弈、紅隊、分支樹） | `structural-decision-stress-test` |
| 協議競態 / 狀態機合約 | `protocol-adversarial-design` |
| 模糊多鏡頭決策 / 產品本質拆解 | `meta-thinking-framework` |
| 對「未來會怎樣」做認識論邊界分類 + 可校準窗口機率 / 不可校準域降格 | **this skill** |

本 skill 是 `structural-decision-stress-test` 的**上游路由器**：本 skill 判定「這個未來問題屬於哪一類」，第三類（含 2b、長視野 2a）委派給 SDST 做條件式警戒。SDST 從不宣稱機率，宣稱「若 H 錯則切換到分支」——這恰好是第三類域唯一不撒謊的輸出形式。兩者形成「機率預測 vs 條件式警戒」的互补分工。

## Self-loop

若使用者在後續對話回報「這個預測 / 分類不準」、或某個機率預測在兌現後被證明失效：
1. 定位失效在哪一層：分類錯（域判錯類）？視野閘沒觸發（長視野穿了短視野衣服）？尾巴被抹平（單一數字 + 免責註腳）？軟改殘餘顯現但沒被症狀指數捕捉？觸發線沒挂（硬改發生但沒標記失效）？
2. 只修正該層的產出 + 受影響的下游，不從頭重跑。
3. 把失效寫進預承諾日志的兌現記錄，作為下次同類問題的路由參考。
4. 若失效原因是「軟改症狀清單漏了某個症狀」→ 補症狀，但標記為描述性回測更新，不是預測性校準。
