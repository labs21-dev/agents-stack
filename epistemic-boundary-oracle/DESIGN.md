# Design — epistemic-boundary-oracle

> 狀態：設計定稿待批准（2026-07-28）。
> 來源：從一段「萬能預言機」架構設計出發，經六輪第一性原理拆解（事後過擬合 → 事前過擬合 → 第三方預登記循環 → 2b 判斷邊界 → 長視野尾巴 → 2a 軟改殘餘）收斂而成。
> 定位：`structural-decision-stress-test` 的上游路由器，不是替代品。

## 0. 目標與邊界

- **目標**：一個會拒絕回答不可校準問題的預測路由器。把「未來會怎樣」的查詢分到三類域，只對可校準窗口輸出機率分布，對不可校準域沉默或降格為條件式警戒。
- **邊界**：
  - 不是預測引擎——不造世界模型、不跑 agent swarm、不算反事實模擬。
  - 不是決策框架——不做承重實體 / 博弈 / 紅隊（那是 SDST）。
  - 唯一產品是「**這個問題屬於哪一類、該用什麼輸出形式、為什麼不是機率**」。
- **核心命題**：可預測性不是架構層數的函數，是該域是否有預先承諾的邊界 + 足夠同分布樣本的函數。加層不會把不可校準的域變可校準。

## 2. 核心設計取捨

### 為什麼是路由器而非預測引擎

預測引擎的價值在「能預測多少」。但可預測性是域性質的函數，不是引擎複雜度的函數。對不可校準域，再強的引擎也只是過擬合放大器。路由器的價值在「拒絕得有多準」——而拒絕是個否定判斷，不需要校準就能給，恰好繞過不可校準域的病。

### 為什麼三類域的判準是「邊界能否預先承諾」而非「有沒有樣本」

樣本數可被事後畫邊界操縱（garden of forking paths）。邊界能否在事件發生前無歧義承諾，是更嚴格也更不可操縱的判準。第一類的邊界被機制釘死（不可操縱），第二類 2a 被制度公布（外部給定），2b 與第三類是判斷（可操縱）。

### 為什麼預承諾協議的適用範圍被收窄到純記賬

最初的設計以為預承諾能擋住所有過擬合。拆解發現：它擋得住事後過擬合（改邊界留證據），擋不住事前過擬合（預測前量身定邊界不留證據）；第三方預登記也補不干净（循環）。所以它只在「邊界已被機制釘死、只需累積樣本」的第一類域有用——純記賬紀律。它不能把判斷邊界的域變可校準。誠 honest 收緊而非誇大協議能力。

### 為什麼 2a 不被一刀切掉

2a 短視野帶的是「可控殘餘的近似可校準」，不是「面具下的第三類」。軟改殘餘不可消除，但可被三層壓住：短視野（壓權重，啟發式）、症狀指數（事後降級）、准入/降級分離（隔離判斷性）。所以 2a 有置信等級，不是二元可/不可。這比把 2a 切掉誠實，也比假裝 2a 乾净誠實。

### 為什麼尾巴防禦用機制不用政策

免責聲明會被忽略（註腳式免責手法）。所以防禦用輸出格式與協議層行為：不可坍縮結構（忽略須顯式做出，可 grep）、視野閘（協議層拒絕，下游拿不到數字）、觸發線（自動標記失效）。mechanism-not-policy——沒禁止忽略，讓忽略必須被顯式做出。

## 3. 與既有 skills 的引用關係

| 需求 | Skill | 關係 |
|------|-------|------|
| 對「未來會怎樣」做認識論邊界分類 | **本 skill** | 路由器 |
| 第三類 / 2b / 長視野 2a 的條件式警戒 | `structural-decision-stress-test` | **下游**：本 skill 委派 |
| 協議競態合約 | `protocol-adversarial-design` | 旁支 |
| 模糊多鏡頭決策 | `meta-thinking-framework` | 旁支 |

關鍵分工：本 skill 輸出**機率**（只在可校準窗口），SDST 輸出**條件式警戒**（「若 H 錯則切換分支」，不需同分布樣本）。SDST 從不宣稱機率——這恰好是第三類域唯一不撒謊的輸出形式。兩者形成「機率預測 vs 條件式警戒」的互补分工。本 skill 是 SDST 的上游：先判定問題屬於哪一類，第三類委派 SDST。

## 5. 待驗證假設 + 驗證方法論

1. **三類域判準在實戰中可操作** → 跑 evals，看每個查詢能否被無歧義分到一類。出現「既像 2a 又像 2b」的高頻邊界 case → 判準需細化。
2. **視野-穩定性比閾值可設定** → 需對每個 2a 域估 regime 歷史穩定半衰期。半衰期本身是描述性統計（可算），但「用過去半衰期推未來穩定性」帶第三類殘餘——閾值應保守（偏低），誠 honest 標記。
3. **軟改症狀清單可回測** → 拿歷史硬改事件回頭檢驗症狀是否領先出現。樣本少（硬改稀有），但是描述性回測非預測校準，門檻較寬。症狀清單漏項 → 補，標為描述性更新。
4. **不可坍縮結構真的擋住坍縮** → 觀察下游使用：是否有人寫 `x.p_outcome_given_regime` 就走（顯式忽略）。顯式忽略可 grep 可審計，比註腳式免責好——但若下游系統性地忽略條件性，說明結構不夠強，需考慮協議層強制（如 tier=exit 時不返回數字鍵）。
5. **SDST 委派真的能接住第三類** → 本 skill 把第三類委派 SDST，需驗證 SDST 對本 skill 路由過來的問題能產出有效條件式警戒。若 SDST 對某些第三類問題也構不出分支樹 → 本 skill 需補「拒絕」路徑（已在 Flow 步驟 3）。

## 6. 反身性自檢

本 skill 是認識論 meta-skill，受反身性威脅。自檢：
- 本 skill 的「可預測性判準」是否自生？→ 部分借統計學既有結論（garden of forking paths、Brier 適用邊界、calibration curve）與物理學的機制錨定觀念（外部 anchor），非全自生。
- 但本 skill 的三類劃分與尾巴防禦未經獨立 eval 驗證（N=1 設計）——誠 honest 標記。`evals/evals.json` 是第一個外部 anchor。
- Self-loop + 預承諾日志兌現記錄是反身性防禦——預測失效時定位是哪一層（分類 / 視野閘 / 尾巴 / 軟改 / 觸發線），而非整個推翻。
- L1 eval 指標須與 L2 真實預測事後驗證雙向校準：eval 高分但實戰預測仍翻車 → eval 劇場，需修正 eval。特別警戒：本 skill 的「拒絕」輸出無法用傳統 Brier 校準（拒絕不產生可兌現預測），需另設「拒絕是否正確」的回溯指標（被拒絕的問題事後是否真的不可校準）。
- 最深反身性威脅：本 skill 聲稱「第三類不可校準」——這個聲稱本身是否可校準？否（它是個否定判斷，第三類的不可校準性無法被校準證明，只能被演繹論證）。誠 honest 標記：本 skill 的根基是演繹而非經驗，它的可靠性來自論證鏈的自洽，不來自校準數據。這也是為什麼 §5 的驗證方法論多為「判準可操作性」「閾值可設定」這類工程驗證，而非「預測準確率」——後者對一個以拒絕為核心產品的 skill 不適用。
