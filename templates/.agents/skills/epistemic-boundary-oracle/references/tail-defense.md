# 尾巴防禦（Tail Defense）

第二類域的機率預測底下都墊著一個不可校準的第三類尾巴：「regime 會不會變」。這個尾巴隨預測視野放大，長視野下吃掉全部。2a 還有一個更深的殘餘：軟重定義——制度不改版本號但改生成機制，症狀滯後且不可完全偵測。

尾巴關不掉（它就是第三類事實，第三類不可校準是已推到底的結論）。本檔做的事是把尾巴從**隱形**變成**可命名、可觀測、被機制約束**，並讓它在結構上**無法被默認抹平**。

## 四種抹平手法（要守住的東西）

抹平的共同結構：**把結構性的條件依賴，坍縮成一個單一數字 + 一句免責**。坍縮一旦發生，條件依賴從承重結構變裝飾。

1. **註腳式免責聲明**。輸出「p = 0.62，假設制度穩定」，然後 0.62 作為單一數字往下游傳，註腳變裝飾。下游決策用 0.62，沒人讀註腳。
2. **不可校準默認成「小」**。因為沒人能證明 R 會變，就默認 P(R 變) ≈ 0。無法證大，就被當成小。把「不可校準」偷換成「可校準且小」。
3. **跨域平均**。把不同制度期間的樣本混在一起算 Brier，假裝 R 一直沒變。樣本變多，同分布性被破壞，校準失效——而失效不會在 Brier 數字上顯形，Brier 看起來反而更好。
4. **長視野穿短視野的衣服**。用短視野校準的 Brier 支撐長視野預測，不標記視野改變了尾巴權重。校準光環從短視野（誠實）借來，用在長視野（不誠實）。

## 結構性防禦（機制，不是政策）

免責聲明會被忽略，所以不能用免責聲明守。用**輸出格式與協議層行為**讓坍縮做不到。

### 防禦 A — 不可坍縮輸出結構

不輸出單一數字，輸出一個結構，機率放在帶條件語義的鍵名裡：

```
{
  regime_ref: "FED_DUAL_MANDATE_v2012",
  regime_source: "institutional",              // 2a: institutional vs 2b: analyst-drawn
  p_outcome_given_regime: 0.62,                // 條件機率，不是機率
  regime_definition_observables: [...],        // R 由哪些可觀測量定義
  trip_wires: [...],                           // 任一斷裂 → 此機率失效，從零重校
  horizon: "18mo",
  horizon_stability_ratio: 0.3,                // 見防禦 B
  soft_redefinition_suspect_index: 0.15,       // 見防禦 D
  confidence_tier: "high",                     // 由嫌疑指數調節
  reform_history: {changes: 3, years: 40, note: "descriptive, not predictive"},
  tail_class: "third-class uncalibratable",
  residual: "soft-redefinition may be underway with symptoms not yet visible; uneliminable, only suppressed by short horizon (heuristic, not calibrated)"
}
```

下游要用 0.62，必須從 `p_outcome_given_regime` 鍵裡取出來——鍵名本身在每個使用點重述「這是條件機率」。忽略仍可能（有人寫 `x.p_outcome_given_regime` 就走），但忽略現在是個**可 grep、可審計的顯式動作**，不是默認。這是 mechanism-not-policy：沒禁止忽略，讓忽略必須被顯式做出。

### 防禦 B — 視野-穩定性比，自動降級閘

算 `horizon / regime 歷史穩定半衰期`。超閾值 → **協議層自動拒絕輸出機率**，降格為第三類路徑（委派 SDST）。拒絕不是註腳，是協議行為——下游拿不到數字。

這把「尾巴會長大」從一個要人記住的提醒，變成一個會自動觸發的閘。長視野第二類預測在這條規則下根本進不了機率路徑——它們被強制走條件式警戒。

### 防禦 C — 硬改觸發線

2a 才能 做乾净：R 的定義直接引用制度公布的版本與其可觀測量（使命條文、議事規則、公布頻率、判定口徑）。任一可觀測量斷裂 → 機率自動標記失效，歷史樣本歸零，需從零重校。

2b 做不到乾净——R 是預測者畫的，沒有制度公布的版本可引用。所以 **2b 不適用此防禦，直接按第三類處理**（見 `domain-classes.md`）。

### 防禦 D — 軟改嫌疑指數（事後降級，不是准入）

軟重定義：制度不改版本號但改生成機制（解釋漂移、構成替換、邊界鬆緊、靜默優先級重排）。可觀測定義沒斷裂 → 觸發線不觸發 → 機率靜默失效，連「標記失效」都做不到。

軟改雖不更新版本號，但在**別的可觀測量**上留痕——委員會投票分歧擴大、相同條文下裁決結果分布漂移、決策措辭語義移動、市場對同一政策信號的反應彈性變化。這些是軟改的**症狀**，不是軟改本身。

- 設「軟改嫌疑指數」：症狀超閾 → **降級置信等級**（high → medium → low），不宣稱「軟改發生了」（確診第三類），而是「校準帶軟改嫌疑，視為窗口邊緣」。
- 嫌疑超上閾 → 退出機率路徑，轉條件式警戒（委派 SDST）。

**關鍵限制：症狀是滯後的。** 等看到投票分歧擴大，軟改可能已進行了一兩屆。所以這個防禦不是預防，是**事後降級**——不能阻止用過一段已失效的 Brier，只能在症狀累積後把置信等級拉下來。窗口的開口往回縮了一段。

### 防禦 E — 准入與降級分離（隔離判斷性）

症狀清單本身是個判斷（「投票分歧擴大意味著慣例在漂移」是個因果假設）。但症狀清單是對**過去**的描述，不是對**未來**的預測——可拿歷史硬改事件回頭檢驗「症狀是否領先出現」（可回測的描述性問題，雖然樣本少）。

所以把准入和降級分離：
- **准入**（允許輸出機率）靠相對乾净的條件：2a + 制度公布邊界 + 短視野 + 硬改觸發線。
- **降級**（調低已輸出機率的置信等級）靠帶判斷但可回測的症狀指數。

判斷性被隔離在降級路徑裡，不污染准入路徑。症狀清單回測過關 ≠ 未來軟改會表現同樣症狀（軟改形式可能創新——又第三類），但這個殘餘被「症狀只用於降級、不用於准入」壓住。

## 不可消除的殘餘（誠實標記）

2a 短視野機率預測永遠帶一個認識論上消除不了的殘餘：**軟改可能正在進行而症狀尚未顯現**。要消除它需能直接觀測生成機制，而生成機制不可觀測正是軟改之所以是軟改的原因。

唯一緩解：**視野夠短**，讓「軟改在這麼短的窗口內累積到顯著」的概率下降。注意這個「概率下降」本身也是判斷，不是校準過的數字——它來自「軟改通常是漸進的」這個描述性觀察，而「漸進軟改在 Δt 內影響多大」又第三類。所以短視野壓低殘餘權重是**合理的啟發式，不是校準結論**。輸出結構裡的 `residual` 欄必須如此標記。

## 2a 誠實可用窗口（最終）

> 2a 域 + 制度公布可觀測邊界 + 短視野（視野-穩定性比低於閾值）+ 硬改觸發線已挂 + 軟改嫌疑指數低於閾值 + 改革歷史標為描述性、非預測性 + 殘餘：軟改可能正在進行而症狀未顯，不可消除，只靠短視野壓低權重（啟發式）。

窗口外（2b、長視野 2a、第三類）一律降格條件式警戒，委派 SDST，不輸出機率。
