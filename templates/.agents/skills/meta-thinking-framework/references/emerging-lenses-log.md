# 額外鏡頭育成日誌（Emerging Lenses Log）

這個檔案記錄六標準鏡頭之外被引入過的額外鏡頭。目的：讓「該加的鏡頭沒加」與「反覆出現的鏡頭該畢業成標準鏡頭」這兩件事可追蹤，使框架隨使用演化。

> 這是模板。真實的鏡頭記錄由使用者在自己的 runtime 累積，不隨模板散布。

## 記錄格式

每筆一個區塊：

```
## [日期] 額外鏡頭名稱 — 用於什麼問題
- 問題類型（見 routing-table.md）：
- 觸發變數：步驟 2 抽出的哪個核心變數需要它
- 反事實對比：硬套六鏡哪一個會漏掉什麼
- 觀察推論摘要：（該鏡頭產出的關鍵洞察）
- 事後驗證：這個鏡頭的洞察事後被證實有效 / 無效 / 待驗
- 累計使用次數：（同類問題）
- 是否達畢業門檻：（是 → 提議納入 routing-table；否 → 仍為臨時鏡頭）
```

## 畢業門檻（建議）

- 同類問題累計 ≥ 3 次，且事後驗證至少 1 次有效 → 提議納入 `routing-table.md`。
- 累計 ≥ 3 次但全部無效 → 標記為「偽需求鏡頭」，不再輕易引入（記錄其失敗原因）。

## [2026-08-14] 資安/信任邊界 — True OS for Agentic World 的到臨長什麼樣
- 問題類型（見 routing-table.md）：系統/agent 架構設計（橫跨產品/商業策略）
- 觸發變數：內核權威的不可繞過性（誰寫 Σ、誰寫 completed、誰發權能票據）
- 反事實對比：硬套逆向思考會把「被繞過」列成一條失敗模式，漏掉不可繞過性是 OS 的定義條件而非風險項、生成面預設不可信、以及 chat 表面一旦擁有 completed/權限就不再是 tty 而是偽內核

## [2026-08-14] 生態/外部性 — True OS for Agentic World 的到臨長什麼樣
- 問題類型（見 routing-table.md）：系統/agent 架構設計（橫跨產品/商業策略）
- 觸發變數：互補品鎖定（別人是否把 skill/agent/工具寫進你的 syscall，而不是繞過你）
- 反事實對比：硬套經濟學會講誘因與轉換成本，漏掉 OS 是「他人寫入你 ABI 之後形成的環境」這一外部性、雞生蛋（沒 app 不成 OS、沒 OS 沒人寫 app）、以及模型實驗室用相容性捕食把獨立內核降級成 libc
- 觀察推論摘要：到臨不是你的 kernel 做完，而是繞過你的人開始變窮——他們的 agent 無法跟別人的工具/狀態/完成位對齊。POSIX 時刻先於 Windows 時刻；MCP 是 USB 不是 OS。
- 事後驗證：待驗
- 累計使用次數：1（同類問題）
- 是否達畢業門檻：否 → 仍為臨時鏡頭
