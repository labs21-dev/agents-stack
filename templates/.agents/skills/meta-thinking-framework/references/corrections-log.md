# 修正記錄（Corrections Log）

這個檔案是自我迭代迴圈的落地目標。當使用者回報某次分析「不準」、或事後證明某個假設錯了時，把修正記錄在這裡，作為下次同類問題的路由參考。

> 這是模板。真實的修正記錄由使用者在自己的 runtime 累積，不隨模板散布。

## 記錄格式

每筆修正一個區塊，欄位如下：

```
## [日期] 題目摘要
- 問題類型（見 routing-table.md）：
- 錯在哪個鏡頭：頂層 / 本質 / 底層邏輯 / 逆向 / 經濟 / 心理
- 原本的假設／產出：
- 實際發生什麼：
- 修正後的產出：
- 給下次的路由提示：（同類問題應該先檢查／加強哪個鏡頭）
```

## 修正記錄

## [2026-09-01] ParallelPaws 一句話定位 — 價值多樣性被砍
- 問題類型（見 routing-table.md）：產品定義 / positioning
- 錯在哪個鏡頭：本質（頂層評價標準一併框錯）
- 原本的假說／產出：把「一句話一眼明」等同「只講一個價值點」，將信/寫真/收藏卡/禮物等價值面當噪音砍剩「記得」一點，產出「你隻貓唔會記得你哋嘅每一日 — ParallelPaws 嗰隻 AI 貓會」
- 實際發生什麼：用戶回報「價值不夠明確，因為 ParallelPaws 有好多價值」— 單軸句壓縮掉產品的價值多樣性，反而講唔清做咩
- 修正後的產出：一句話的正確結構是「一個來源 → 多種形態」：所有價值共有的 parent 是「你同貓嘅每一日，變成留得住、睇得返、送得出嘅嘢」；五形態（信/寫真/卡/禮物/日曆）= 同一回憶的變形。核心句改為來源→形態結構，單軸 hook 句降級為開場情感錨
- 給下次的路由提示：同類「一句話講清產品」題，【本質】抽核心時先問「呢個產品嘅價值係一點定一譜？」— 若產品有多個付費面/產出面，一句話嘅正確結構是「上層概念 + 形態列舉」，唔係「挑一個講」；「留得住/睇得返/送得出」式動詞三連係壓縮多價值嘅可用型

## [2026-09-01] 同題二次修正 — 價值清單仍然殘缺
- 問題類型（見 routing-table.md）：產品定義 / positioning（連續第二次同題）
- 錯在哪個鏡頭：頂層+本質（雙錯，同一根因）
- 原本的假說／產出：「來源→形態」結構，五形態清單（信/寫真/卡/禮物/日曆）仍由對話記憶構成；完全漏掉房間 5 個 QuickAction（食飯/補水/蕃茄鐘/呼吸/情緒信紙）代表的整條 self-care 價值軸、信箋系統、明信片畫風系統
- 實際發生什麼：用戶直接指出「你無真正分析出價值」— 兩次壓縮都建立在未盤點的殘缺價值清單上
- 根因：分析對象是「我記得的產品」而非產品本身。正確做法是先 grep codebase 盤點真實 surface（RoomQuickActionDock、DayLogModels、TogetherTimeService、Share/、Chat/），其中 code 註解直接寫明 quick actions 是 "rituals, not habit KPI pills" — self-care 儀式軸一直寫在 code 裡
- 修正後的產出：ParallelPaws 是雙引擎產品——①照顧引擎：5 個 quick action 以「照顧貓」包住「照顧自己」（留存結構）；②記憶引擎：日記/相/情緒流入記憶源，變形為信/寫真/卡/禮物（情感護城河+收入面）。一句話最終版：「照顧一隻 AI 貓，其實係照顧自己；而佢，記住你哋嘅每一日。」
- 給下次的路由提示：同類「我的產品是什麼/價值是什麼」題，【本質】抽核心之前必須先做「產品盤點」步驟——從 code（models enum、views 目錄、service 層）數齊實際存在的價值面，禁止從對話記憶或先前結論出發。記憶≠產品，code 才是單一事實源（同 verify-claims-with-logs-before-root-cause 同構）

## 候選工具 / 步驟（非鏡頭）

> 框架的演化機制有「新鏡頭」的槽（`emerging-lenses-log.md`），但**沒有「新工具 / 新步驟」的槽**。步驟 8 的 epistemic-mapping 工具（如四象限）不是鏡頭，塞不進 lens log。在此記錄此類候選，待累積驗證後再決定是否納入標準模板。同樣適用 `skill-evolution` 的 reflexivity 防線：N=1 不立法，先當候選。

### 2026-07-28 四象限 known/unknown 矩陣 — 候選步驟 8 工具
- **來源**：一次多輪產品分析實戰（MCP agent 產品定義）
- **用途**：在步驟 8「待驗證假設」之後，把雙方認知地圖畫成四象限——共識 / 你知我不知（須問）/ 雙方未知（須設計實驗）/ 我知你需小心。用於找出「最大空白」與「最危險的默認假設」。
- **為何記為候選不立法**：僅 1 次使用（N=1），且全在產品題。對純技術 / 純組織題是否真釐清 vs 湊數，未驗。
- **畢業門檻**：連續 ≥2 次非產品題自然用到且有效，總計 ≥3 次有效 → 提議納入 `analysis-template.md` 步驟 8 區塊。
- **未達門檻前**：不寫進標準模板；使用者可自行在產品題中選用。
