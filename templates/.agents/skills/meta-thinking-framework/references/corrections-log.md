# 修正記錄（Corrections Log）

這個檔案是自我迭代迴圈的落地目標。當使用者回報某次分析「不準」、或事後證明某個假設錯了時，把修正記錄在這裡，作為下次同類問題的路由參考。

> 這是模板。真實的修正記錄由使用者在自己的 runtime 累積，不隨模板散布。

## 記錄格式

每筆修正一個區塊，欄位如下：

```
## [日期] 題目摘要
- 問題類型（見 routing-table.md）：
- 錯在哪個鏡頭：頂層 / 本質 / 底層邏輯 / 逆向 / 經濟 / 心理
- 原本的假設／產出：
- 實際發生什麼：
- 修正後的產出：
- 給下次的路由提示：（同類問題應該先檢查／加強哪個鏡頭）
```

## 候選工具 / 步驟（非鏡頭）

> 框架的演化機制有「新鏡頭」的槽（`emerging-lenses-log.md`），但**沒有「新工具 / 新步驟」的槽**。步驟 8 的 epistemic-mapping 工具（如四象限）不是鏡頭，塞不進 lens log。在此記錄此類候選，待累積驗證後再決定是否納入標準模板。同樣適用 `skill-evolution` 的 reflexivity 防線：N=1 不立法，先當候選。

### 2026-07-28 四象限 known/unknown 矩陣 — 候選步驟 8 工具
- **來源**：一次多輪產品分析實戰（MCP agent 產品定義）
- **用途**：在步驟 8「待驗證假設」之後，把雙方認知地圖畫成四象限——共識 / 你知我不知（須問）/ 雙方未知（須設計實驗）/ 我知你需小心。用於找出「最大空白」與「最危險的默認假設」。
- **為何記為候選不立法**：僅 1 次使用（N=1），且全在產品題。對純技術 / 純組織題是否真釐清 vs 湊數，未驗。
- **畢業門檻**：連續 ≥2 次非產品題自然用到且有效，總計 ≥3 次有效 → 提議納入 `analysis-template.md` 步驟 8 區塊。
- **未達門檻前**：不寫進標準模板；使用者可自行在產品題中選用。
