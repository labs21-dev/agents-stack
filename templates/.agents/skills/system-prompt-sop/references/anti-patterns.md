# 失敗模式（改寫 / 評審別人 prompt 時的快篩清單）

九個已確認的模式。評審時逐項對照；改寫時每修一處引用對應編號。

## 1. 原則當 vibe
原則無 why、無可觀測訊號、無 eval 覆蓋 → 不可證偽的品味之爭。
**修法**：補訊號 + 綁 eval case；綁不出來的降階為規則或刪除。

## 2. 能力錯配
原則假設的判斷超出模型現有分佈 → 原則零效果，症狀是「模型不聽話」，
誤診為紀律問題。
**修法**：跑 capability probe；不通過就降階（帶觸發條件的規則 / 範例），
不是改措辭。

## 3. 紅線只寫 prompt
「P0 永不違反」放在 in-context token 裡 = 法律寫成建議。
**修法**：harness 強制（審核閘 / 權限 / deny-list / 程式檢查）；
prompt NEVER 降級為提醒備份。

## 4. 證據錯置
用 Constitutional AI（訓練期、原則進權重）論證 prompt 寫法（推論期、
原則只是 token）；把 26-principles / 54% 這類未復現、單模型、依條目而異
的數字當承重牆。
**修法**：引用時標「未復現 / 方向性參考」；結論只建立在機制推導 + 自有
probe 數據上。

## 5. 跨模型移植神話
同一套原則原封搬去另一個模型。原則移植性與能力差距成反比。
**修法**：搬結構與路由結果；每模型重跑 probe。弱模型偏好帶觸發條件的
規則與範例。

## 6. 原則牆
以為原則豁免注意力天花板，30 條原則照樣堆。原則是壓縮率較好的牆。
**修法**：預算審計；超量重新路由（多數條目本屬 validator/harness）。

## 7. cache 與遵循的矛盾沒被解決
所有約束前置吃 cache，指望長任務中後段還被記得。此矛盾 prompt 內無解。
**修法**：會漂移的行為外移 harness（重注入 / 狀態檢查 / 階段閘）。

## 8. happy-path 範例
範例展示一切順利的情境 → 錨定的是本來就會的行為，等於沒訓練。
**修法**：換成生產失敗樣本，帶輸入 → 推理鏈 → 正確動作。

## 9. 指導碎進 tool description
複雜流程、判斷標準塞進 tool schema → 注意力碎片化、cache 不友好。
**修法**：複雜指引收進 system prompt；tool schema 只留「何時不用」類
短政策——工具的「何時不要用」比「何時用」更決定正確率。
