# 放權前置清單（Autonomy Checklist）

> 每次要把 agent 的權限往上一級放（自動合併、雲端 agent、擴大自動化域）之前過一遍。
> **全部 ✅ 才放權。任何一項 ✗ → 停在本級，補齊後再來。**
> 核心不等式：放權等級 ≤ 驗證基建等級。
> 自主目標的完整表述：**全自主 ≠ 沒有閘門，= 閘門分級自動化**——可機器斷言的自動化、價值判斷與不可逆的保留、時序敏感的搬到邊緣（intake 或 delivery），人的角色從流程一環變成例外處理者。

## 放權對象

- 域範圍：<哪些 feature/目錄/任務類型>
- 權限動作：<自動合併 PR / 自動部署 / 自動建 issue / 雲端自主任務>
- 擬放權等級：<單任務自驗證 → 單域自動合併 → 多域 → 雲端 agent>

## 前置檢查

### A. 地圖覆蓋（L2）
- [ ] 域內每個 feature 有 feature map 卡
- [ ] 每張卡含可機器執行的驗證步驟
- [ ] 每張卡的地圖時效錨在 <30 天內

### B. 紅線覆蓋（L3）
- [ ] 域內常見違規模式有 lint / CI 紅線
- [ ] 每條紅線用已知壞例子反測過真的會紅
- [ ] warn 模式誤報裁決已完成（無未處理誤報）

### C. 回歸證據（L4）
- [ ] eval 任務集覆蓋本域（≥5 個真實任務，含 ≥1 個陷阱任務）
- [ ] 近 3 次全量回歸全綠
- [ ] 最近 10 次真實任務中 agent 自驗證結論與事後事實一致率 ≥ 90%

### D. 監控與收權
- [ ] 放權監控指標 = **兩把尺**：
  - 信任軸：revert rate + 事後 bug 率（**不含**吞吐量/PR 數——那是結果指標，不作放權輸入）
  - 自主軸：question rate——每 10 個任務中人被介入（問答/截圖/補需求）的次數
- [ ] 指標閾值已定：revert rate < __%、事後 bug 率 < __%、question rate < __ 次/10 任務
- [ ] **兩把尺一起過線才叫自主**：revert 低 + question 高 = 溫室自主（靠人盯出來的）；question 低 + revert 高 = 悶頭猜（更危險，靜默猜測的賬單只是還沒到）
- [ ] 收權路徑：誰有權收、怎麼收、多久能收完（<分鐘級）
- [ ] 自動收權觸發器：任一把尺超閾 → 自動降回上一級，不等人工發現

### E. 自主畫像（SOP 質量）
- [ ] 本域的任務劇本已過 question audit：每個決策點三選一——有預設 / 可查環境 / 註冊為合法升級點
- [ ] 註冊的升級點有明確觸發條件（改變結論 ∧ 推不出來 ∧ 不可逆或爭議大），無「視情況問用戶」逃生口
- [ ] 問題集中在邊緣：**intake 一輪問完 → 執行零插手 → 交付附「此處我選了X」標記清單**供事後抽查
- [ ] 無靜默猜測路徑（有預設/有斷言/問人，三者之外不存在）

## 裁決

- 全 ✅ → 放權，記錄日期與域範圍
- 有 ✗ → 停在本級；列出缺項對應的最小補齊動作
- **每次擴域重跑本清單；域不同，結論不繼承**
