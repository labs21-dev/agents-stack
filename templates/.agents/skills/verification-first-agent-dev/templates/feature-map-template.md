# Feature Map 卡模板

> 一個 feature 一張卡。放在 `.agent/feature-map.md`（或按 feature 拆多檔）。
> 寫作對象是 context-limited 的 agent：入口、路徑、代碼位置、驗證步驟，缺一不可。
> 只寫「掃代碼掃不出來或要花很久才能拼出來」的東西；代碼裡顯而易見的不寫。

## <Feature 名>

### 入口
主窗口 → <菜單/路由/頁面路徑>（含快捷鍵，若有）

### 關鍵 UI 位置
- <搜索框 / 按鈕 / 狀態區>：<頁面內位置描述>
- （可含 DOM selector / accessibility id，若穩定）

### 驗證步驟（這是卡的承重部分，必須可機器執行）
1. <造什麼數據>
2. <什麼操作>
3. <看到什麼才算對——斷言查結果>
4. <邊界：至少一個>
5. <恢復原狀驗證，若適用>

### 相關代碼
- `src/features/<feature>/` — <一句話說明內部分工>
- <關鍵文件：職責>

### 常見問題（agent 最容易錯的地方）
- <例：搜索必須忽略大小寫>
- <例：中文不能亂碼>
- <例：空關鍵詞不能過濾列表>

### 地圖時效錨（必填）
- 本卡驗證步驟最後確認通過的日期：<日期>
- **驗證步驟失敗時的第一假設是地圖過期，不是代碼錯**——先核對入口與 DOM 是否變化，更新本卡，再查代碼。
